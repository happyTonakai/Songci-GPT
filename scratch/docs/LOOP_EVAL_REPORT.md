# 循环训练 (Loop Training) 评估报告

## 1. 实验概述

### 1.1 背景

受 LoopLM/Ouro 论文启发，我们在 Songci-GPT 的 6 层 MoE 模型上实现了两种循环训练机制，并结合 ERNIE 5.0 弹性训练进行评估。循环训练的核心思想是：通过重复应用同一组层来增加模型的有效计算深度，而不增加参数量。

### 1.2 两种循环机制

| 机制 | 来源 | 原理 | KV Cache 兼容性 |
|------|------|------|----------------|
| **Per-Block Loop** | LoopLM/Ouro 论文 | 整个 6 层 block 作为整体循环 T 次 | 不兼容（训练/推理深度不对称） |
| **Per-Layer Loop** | 本项目设计 | 每层独立循环 t 次后再进入下一层 | 兼容 |

### 1.3 模型配置

两个模型使用相同的基座配置：

| 参数 | 值 |
|------|-----|
| 架构 | GPT + MoE |
| 层数 | 6 |
| 每层专家 | 4 路由专家 (top-1) |
| embedding_dim | 512 |
| hidden_dim | 2048 |
| num_heads | 8 |
| 总参数量 | ~41.8M |
| 训练数据 | 宋词语料 |
| 训练轮次 | 10 epochs |

### 1.4 循环训练配置

**Block Loop 模型** (`configs/loop_block.yaml`)：

| 参数 | 值 |
|------|-----|
| block_loop_count | 4（默认循环 4 次） |
| block_loop_drop_prob | 0.25（25% 概率降级） |
| block_loop_levels | [1, 2, 3]（降级目标） |
| batch_size | 8 |

**Layer Loop 模型** (`configs/loop_layer.yaml`)：

| 参数 | 值 |
|------|-----|
| layer_loop_count | 4（每层默认循环 4 次） |
| layer_loop_drop_prob | 0.25（25% 概率降级） |
| layer_loop_levels | [1, 2, 3]（降级目标） |
| batch_size | 8 |

> 训练时 25% 概率将循环次数从 4 降到 1/2/3，使模型学会在不同循环次数下工作。

## 2. 评估方法

### 2.1 评估指标

使用 SongEval 格律评估系统：

| 指标 | 权重 | 说明 |
|------|------|------|
| 结构匹配率 | 40% | 句数、每句字数是否符合词牌标准 |
| 平仄准确度 | 40% | 每个字的平仄是否符合标准模板 |
| 押韵一致性 | 20% | 韵脚位置的韵部是否一致 |
| **综合得分** | - | 加权计算，满分 100 |

### 2.2 评估流程

- **词牌库**：75 个常用词牌
- **样本量**：每个弹性级别 525 个样本（75 词牌 x 7 样本）
- **生成参数**：temperature=1.0, top_k=100, top_p=0.9, max_len=256
- **弹性级别**：1x / 2x / 3x / 4x（循环次数）

### 2.3 Block Loop 的 KV Cache 问题

Block Loop 在推理时存在 **KV Cache 深度不对称** 问题：

- **训练时**：每个 token 都经过 T 次完整 block 循环，所有 token 深度相同
- **KV Cache 推理时**：已缓存的 context token 冻结在深度 T，而新生成的 token 从深度 1 开始
- **后果**：新 token 与 context token 的表示空间不一致，导致生成质量严重退化

验证实验（logits 对比）：max_diff=9.31，top-10 overlap 仅 10%，证实 KV Cache 与 Block Loop 不兼容。

因此 Block Loop 评估时 **禁用了 KV Cache**，逐 token 重新计算整个序列。Layer Loop 不存在此问题，每层的循环在 transformer encoder 内部独立完成。

## 3. 评估结果

### 3.1 Block Loop 弹性级别对比

| 指标 | 1x | 2x | 3x | 4x |
|------|-----|-----|-----|-----|
| 结构匹配率 | 56.38% | 77.33% | 78.10% | **81.52%** |
| 平仄准确度 | 80.87% | 86.65% | 86.20% | **87.30%** |
| 押韵一致性 | 40.79% | 50.96% | 56.32% | **60.40%** |
| **综合得分** | 66.06% | 76.97% | 78.30% | **80.60%** |

**趋势**：单调递增，1x -> 2x 提升最大 (+10.91%)，之后边际递减。

### 3.2 Layer Loop 弹性级别对比

| 指标 | 1x | 2x | 3x | 4x |
|------|-----|-----|-----|-----|
| 结构匹配率 | 54.86% | 72.38% | **77.33%** | 74.67% |
| 平仄准确度 | 80.43% | 85.52% | **86.89%** | 85.82% |
| 押韵一致性 | 43.41% | 54.63% | 60.13% | **60.89%** |
| **综合得分** | 65.67% | 75.70% | **79.19%** | 77.82% |

**趋势**：3x 达到峰值，4x 略有下降 (-1.37%)，存在收益拐点。

### 3.3 汇总对比

| 模型 | 1x | 2x | 3x | 4x | 最佳 |
|------|-----|-----|-----|-----|------|
| **Block Loop** | 66.06% | 76.97% | 78.30% | **80.60%** | 4x (80.60%) |
| **Layer Loop** | 65.67% | 75.70% | **79.19%** | 77.82% | 3x (79.19%) |

### 3.4 弹性降级代价

| 模型 | 最佳 -> 1x 降幅 | 最佳 -> 最差级别降幅 |
|------|----------------|-------------------|
| Block Loop | 80.60% -> 66.06% = **-14.54%** | -14.54% (4x -> 1x) |
| Layer Loop | 79.19% -> 65.67% = **-13.52%** | -13.52% (3x -> 1x) |

## 4. 分析与讨论

### 4.1 两种循环机制对比

| 维度 | Block Loop | Layer Loop |
|------|-----------|------------|
| 最佳综合得分 | **80.60%** (4x) | 79.19% (3x) |
| 最佳循环次数 | 4x（单调递增） | 3x（有拐点） |
| 1x baseline | 66.06% | 65.67% |
| KV Cache 兼容 | **不兼容** | 兼容 |
| 推理速度 | 慢（无 KV Cache，O(n^2)） | 正常（有 KV Cache） |
| 实现复杂度 | 简单（外层循环） | 中等（每层内循环） |

### 4.2 关键发现

1. **两个模型的 1x baseline 几乎一致**（66.06% vs 65.67%），说明训练配置等效，对比公平。

2. **Block Loop 4x 整体最强**（80.60%），比 Layer Loop 最佳（3x, 79.19%）高 1.41 个百分点。整个 block 循环提供了更深度的计算，对格律学习有帮助。

3. **Layer Loop 在 3x 达到峰值后 4x 下降**，说明每层循环 4 次可能过度计算，导致过拟合或梯度问题。3x 是更优的部署选择。

4. **弹性降级代价显著**：从最佳级别降到 1x，两个模型都损失约 14 个百分点。这表明循环训练确实学到了利用额外计算的能力，但也意味着降级部署需要权衡质量损失。

5. **Block Loop 的 KV Cache 不兼容是致命缺陷**：推理时必须禁用 KV Cache，速度为 O(n^2)，不适合实际部署。Layer Loop 没有这个问题。

### 4.3 与 ERNIE 5.0 弹性训练的对比

| 维度 | ERNIE 5.0 弹性训练 | 循环训练 |
|------|-------------------|---------|
| 目标 | 同一参数在不同深度/宽度/稀疏度下工作 | 同一参数在不同循环次数下工作 |
| 降级方式 | 跳层、缩减专家、缩减 top-k | 减少循环次数 |
| 降级代价 | Width/TopK 小 (~3 分)，Depth 大 (~14-49 分) | 约 14 分（从最佳到 1x） |
| 推理兼容 | 完全兼容 KV Cache | Block 不兼容，Layer 兼容 |
| 可组合性 | 三个维度独立 | 可与弹性训练叠加 |

### 4.4 部署建议

| 场景 | 推荐方案 | 预期得分 | 说明 |
|------|---------|---------|------|
| 最高质量 | Layer Loop 3x | 79.19% | 最佳平衡点，KV Cache 兼容 |
| 降级部署 | Layer Loop 2x | 75.70% | 牺牲 3.5 分换取 33% 计算节省 |
| 极简部署 | Layer Loop 1x | 65.67% | 等效原始 6 层模型 |
| Block Loop | **不推荐部署** | - | KV Cache 不兼容，推理太慢 |

---

## 5. 结论

1. **循环训练有效**：两种循环机制都成功学到了利用额外计算的能力，4x/3x 相比 1x 提升约 14 个百分点。

2. **Layer Loop 是更实用的选择**：虽然 Block Loop 4x 得分最高（80.60% vs 79.19%），但 Layer Loop 与 KV Cache 兼容，推理效率高，是实际部署的唯一可行方案。

3. **3x 是 Layer Loop 的最佳配置**：超过 3x 后收益递减甚至下降，建议部署时使用 3x。

4. **弹性降级需要权衡**：从 3x 降到 1x 损失约 14 分，部署时需要根据计算预算决定循环次数。

5. **Block Loop 的 KV Cache 问题是根本性限制**：训练/推理的深度不对称无法通过工程手段解决，除非重新设计训练流程（如 PLT 的 KV Cache Sharing + Gated Sliding-Window Attention）。

## 附录：实验环境

- GPU: NVIDIA GPU (12GB VRAM)
- 模型大小: ~41.8M 参数（6 层 MoE）
- 评估样本: 525 条/配置（75 词牌 x 7 样本）
- Block Loop 评估耗时: ~30 分钟/级别（无 KV Cache，较慢）
- Layer Loop 评估耗时: ~10 分钟/级别
- 评估框架: SongEval（结构 40% + 平仄 40% + 押韵 20%）
